# データベースバックアップ・復元 (Dropbox API) 実装記録

## 1. 目的
システムの継続性を確保するため、Dropbox API を使用してデータベースのバックアップを外部クラウドストレージに保存し、障害時やデータ移行時に迅速に復元できる機能を実装する。

## 2. 実装概要
Django環境に最適化した実装を行い、OAuth 2.0 (Refresh Token対応) を使用して長期的な無人運用を可能にしている。単なるバックアップだけでなく、Web UIからの履歴参照とワンクリック復元に対応。

## 3. 技術仕様

### 3.1 使用ライブラリ・ツール
- `dropbox`: Python 用公式 SDK。
- `mysqldump`: MySQL データベースのダンプ作成用。
- `mysql`: データベース復元（リストア）時のインポート用。
- ※ Dockerコンテナ (`web`) 内に `default-mysql-client` をインストールし、パスを通済み。

### 3.2 データモデル (`apps/accounts/models.py`)
`DropboxToken` モデルで認証情報を永続化。`service_name` は一意。

| フィールド名 | 型 | 説明 |
| :--- | :--- | :--- |
| `service_name` | CharField | サービス名（'backup' 固定、`unique=True`） |
| `access_token` | TextField | 現在のアクセストークン |
| `refresh_token` | TextField | リフレッシュトークン（長期利用に必須） |
| `account_name` | CharField | Dropbox アカウント表示名 |
| `expires_at` | DateTimeField | アクセストークンの有効期限 |

### 3.3 サービス層 (`apps/adjustments/services/dropbox_service.py`)
`DropboxService` クラスにより以下の機能を提供。
- **認証管理**: トークンの有効性確認、自動リフレッシュ。
- **ファイル操作**: 
  - `upload_file`: 大容量ファイル（150MB超）のチャンクアップロード対応。
  - `list_backups`: Dropbox上の履歴取得。サーバー時刻(UTC)を日本時間(JST)に変換して返却。
  - `download_file`: 復元用のダウンロード機能。
- **バックアップ実行 (`create_db_backup`)**:
  - `mysqldump` を使用。整合性確保のため `--single-transaction`, `--quick`, `--routines`, `--events`, `--triggers` を適用。
  - 接続エラー回避のため `--skip-ssl` を適用。
  - 一時的な `my.cnf` (chmod 600) を使用して、コマンドライン引数からのパスワード露出を完全に防止。
- **復元実行 (`restore_db_from_backup`)**:
  - Dropboxから一時ディレクトリにダウンロード、解凍、`mysql` コマンドによるインポート。
  - 実行前に監査ログへの記録と、エラー時の機密情報マスキングを実施。

## 4. 機能要件

### 4.1 バックアップ・復元対象
- MySQL データベースの全テーブル。
- ファイル形式: `.sql.gz` (gzip 圧縮)

### 4.2 保存・表示ルール
- ファイル名: `db_backup_yyyyMMdd_HHmmss.sql.gz` (日本時間 JST)
- 保存先: `/backups/YYYY/MM/DD/`
- 表示: Web UI上ではすべて日本時間で表示。

### 4.3 UI/UX
- **独立した管理画面**: ハンバーガーメニューに「バックアップ管理」を新設。
- **バックアップ作成**: 進捗をトースト通知。作成完了から1.5秒後にリストを自動リフレッシュ。
- **復元機能**: 強力な警告（赤色表示）とカスタムダイアログによる最終確認を経て実行。実行後は自動的に画面をリロード。

### 4.4 セキュリティ
- **管理者限定**: Web UIのメニュー、APIエンドポイントともに `admin` 権限を厳格にチェック。
- **CSRF対策**: 復元実行等のPOSTリクエストにおいてCSRFトークンを検証。
- **機密情報の隠蔽**: ログ出力時、スタックトレースやエラーメッセージに含まれるデータベースパスワードを自動的に `********` に置換（マスキング）。

## 6. スケジュール実行
- **実行頻度**: 毎日1回、深夜帯に cron 等で定期実行。
- **手動実行**: Web UI（バックアップ管理モーダル）から随時実行可能。
- **実装手段**: Django管理コマンド `python manage.py backup_db` を作成し、システムの cron またはコンテナ外部のスケジューラーから呼び出す。

## 7. 保持ポリシー (Retention Policy)
Dropbox ストレージの効率的な利用と、必要な時点への遡及を可能にするため、以下のルールで古いバックアップを自動削除する。

1. **直近世代管理**: 
   - 実行タイミングに関わらず、最新のバックアップデータを **5個** 常時保持する。
2. **月次アーカイブ**: 
   - 過去 **3ヶ月分** の各月末（その月の最終バックアップ）データを保持する。
3. **削除の実行**:
   - 上記 1 または 2 のいずれかの条件に合致しない古いファイルは、バックアップ実行後の `clean_old_backups` メソッドにより自動的に削除される。
