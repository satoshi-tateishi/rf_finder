# ログ監査機能 (Audit Log) 実装計画

## 1. 目的
システムの利用状況を可視化し、セキュリティの向上と運用実態の把握を行う。特に「誰が」「いつ」「どのデータに対して」「どのような操作（出力・送信）を行ったか」を記録する。

## 2. ログ記録対象
ユーザーからの要望に基づき、以下の項目を記録対象とする。

### 2.1 基本ログ
- **ログインログ**: 誰がいつログインしたか（IPアドレス含む）。
- **認証失敗ログ（提案）**: 不正アクセスの兆候を検知するため、ログイン失敗時も記録する。

### 2.2 出力・送信ログ
- **PDFダウンロード**: 運用調整届PDFの生成・ダウンロード操作。
- **Excelダウンロード**: 特ラ機構指定Excelの生成・ダウンロード操作。
- **WSM CSVエクスポート**: ゼンハイザーWSM用CSVの出力操作。
- **メール送信**: 特ラ機構への運用調整メール送信操作（送信先、成功/失敗のステータス含む）。

### 2.3 追加提案ログ（運用保守用）
- **データインポートログ**: 総務省データの取り込みや郵便番号データの更新操作。
- **管理者操作ログ**: 管理画面でのユーザー追加・変更、施設情報のマニュアル更新。
- **重要な設定変更**: メールテンプレートやシステム設定の変更。

## 3. 実装方針

### 3.1 データモデル
`AuditLog` モデルを新規作成する。既存の `accounts` アプリ内に実装するか、独立した `audit` アプリを作成する。

| フィールド名 | 型 | 説明 |
| :--- | :--- | :--- |
| `user` | ForeignKey | 操作を行ったユーザー（匿名の場合は null） |
| `action` | CharField | 操作種別（LOGIN, PDF_EXPORT, EXCEL_EXPORT, CSV_EXPORT, EMAIL_SEND等） |
| `description` | TextField | 操作の詳細（ファイル名、送信先アドレス、催事名など） |
| `ip_address` | GenericIPAddressField | 操作元のIPアドレス |
| `timestamp` | DateTimeField | 操作日時（自動付与） |
| `content_type` | ForeignKey | (任意) 関連するモデル（例: OperationAdjustment） |
| `object_id` | PositiveIntegerField | (任意) 関連するオブジェクトのID |

### 3.2 ログの記録タイミング
- **ログイン**: Django標準の `user_logged_in` シグナルを利用。
- **ファイル出力**: 各View、または `pdf_service`, `excel_service`, `wsm_service` 内の生成完了時に記録。
- **メール送信**: `email_service` 内の送信成功/失敗確定時に記録。

### 3.3 管理画面 (Admin Interface)
- **アクセス制限**: `is_staff` かつ `is_superuser` のユーザーのみ閲覧可能とする。
- **機能**:
    - 一覧表示（日時降順）。
    - ユーザー、操作種別、期間によるフィルタリング。
    - ログ自体の編集・削除は原則禁止（ReadOnlyAdmin）。

## 4. 画面イメージ（管理画面）
- ダッシュボードに「監査ログ」メニューを追加。
- 検索窓で「ユーザー名」や「催事名」でログを検索可能。

## 5. ステップ
1. `AuditLog` モデルの定義とマイグレーション。
2. ユーティリティ関数 `log_action(user, action, description, request=None, obj=None)` の作成。
3. 各サービスおよびViewへのログ埋め込み。
4. 管理画面の設定（ReadOnly, Filter, Search）。
5. テストコードによる記録確認。
